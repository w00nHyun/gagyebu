# 가계부

지출 내역과 예산을 관리하고 월별 소비 흐름을 확인할 수 있는 개인 가계부 웹 애플리케이션입니다.

단순히 지출을 기록하는 기능을 넘어, 반복되는 고정 지출을 자동으로 반영하고 월별 예산과 소비 통계를 한곳에서 확인할 수 있도록 개발했습니다.

개인 프로젝트로 진행했으며 **Express 기반 백엔드 로직, MongoDB 데이터 처리, 사용자 인증 및 통계 구현**을 중심으로 개발했습니다. 화면은 EJS와 Bootstrap 기반 템플릿을 활용하고 서버 데이터 연결에 필요한 부분을 수정했습니다.

| 구분 | 내용 |
| --- | --- |
| 프로젝트 형태 | 개인 프로젝트 |
| 핵심 역할 | 백엔드 설계 및 구현 |
| 주요 관심사 | 인증, 데이터 모델링, 월별 조회, 반복 지출 처리 |

## 담당 구현

- Express 기능별 라우터 설계 및 분리
- MongoDB 기반 지출 내역 CRUD
- Google OAuth 2.0 로그인
- JWT와 HTTP-only Cookie 기반 사용자 인증
- 사용자별 지출 및 예산 데이터 분리
- 지출 내역 날짜 구조 통합 및 유효성 검사
- 쿼리 파라미터를 이용한 월별 지출 조회
- 정기 고정 지출의 월별 자동 생성
- 월간·연간 예산과 사용 금액 계산
- MongoDB Aggregation을 이용한 월별 통계 집계
- 서버 데이터와 EJS 템플릿 연결

## 주요 기능

### 지출 관리

사용자는 지출 내역을 등록, 조회, 수정, 삭제할 수 있습니다. 월을 이동하며 해당 기간의 지출만 조회할 수 있고 날짜순으로 정렬된 내역과 월 지출 합계를 확인할 수 있습니다.

### 고정 지출 자동 반영

월세와 구독료처럼 반복되는 지출을 고정 지출로 등록할 수 있습니다. 마지막으로 반영된 월을 기준으로 누락된 내역을 확인하고 현재 월까지 자동 생성합니다.

### 예산 관리

월간 및 연간 예산을 설정하고 실제 사용 금액, 남은 금액, 예산 사용 비율을 확인할 수 있습니다.

### 달력 및 통계

달력에서 날짜별 지출 내역과 합계를 확인할 수 있습니다. 월별 통계에서는 카테고리, 이벤트, 고정비 여부에 따라 집계된 소비 흐름을 제공합니다.

## 기술적 고민

### 날짜 데이터 구조 통합

초기에는 거래 날짜를 `year`, `month`, `day` 필드로 나누어 저장했습니다. 이 구조는 조회와 화면 출력 과정에서 날짜를 반복적으로 조합해야 한다는 문제가 있었습니다.

날짜를 `YYYY-MM-DD` 문자열로 통합해 데이터 구조를 단순화하고, 문자열 범위 비교만으로 날짜순 정렬과 월별 조회가 가능하도록 개선했습니다.

### 사용자별 데이터 접근 제한

지출, 고정 지출, 예산 데이터에 `userId`를 저장했습니다. 데이터를 조회하거나 수정할 때 로그인한 사용자의 ID를 조건에 포함해 사용자 간 데이터가 분리되도록 구성했습니다.

### 고정 지출 날짜 보정

31일에 등록한 고정 지출을 2월에 생성하는 경우처럼 같은 날짜가 존재하지 않을 수 있습니다. 각 월의 마지막 날짜를 계산하고 등록된 일자와 비교해 유효한 날짜로 보정했습니다.

### 월별 통계 집계

선택한 월의 거래만 먼저 필터링한 뒤 MongoDB `$facet`을 사용했습니다. 카테고리별, 이벤트별, 고정비별 통계를 한 번의 Aggregation 요청으로 집계하도록 구성했습니다.

## 프로젝트 구조

```text
src/
├─ config/          # MongoDB 및 Passport 설정
├─ middleware/      # 인증, 입력 검증, 고정 지출 동기화
├─ routes/          # 기능별 Express 라우터
├─ types/           # TypeScript 타입
└─ server.ts        # 애플리케이션 진입점

views/              # EJS 화면 템플릿
public/             # CSS 정적 파일
```

## 향후 개선 방향

- 고정 지출 설정과 실제 거래 내역을 독립된 데이터로 관리하고 `regularId`로 생성 출처를 추적하는 구조 검토
- 기능이 확장될 경우 라우터의 비즈니스 로직을 서비스 계층으로 분리해 책임과 테스트 범위 명확화
- 날짜 경계값과 고정 지출 자동 생성처럼 오류 가능성이 높은 로직부터 테스트 코드 작성
